INCIDENT REPORT
Subject: “Site Can’t Be Reached” Internet Interruption on Ubuntu System

Date: June 2026
System: Ubuntu Linux Desktop
User: Ray Andrade
Project Impacted: Bible Study Access, TheRayCode Workflow, Browser Connectivity

---

## INCIDENT SUMMARY

The system experienced repeated browser failures displaying messages such as:

* “This site can’t be reached”
* “ERR_ADDRESS_UNREACHABLE”

The interruption prevented access to important online resources, most notably Bible study websites and related study workflows. The issue also affected general browsing reliability and interrupted ongoing development and content creation activities on the Ubuntu machine.

---

## INITIAL SYMPTOMS OBSERVED

1. Browser pages would not load.
2. Bible study websites became inaccessible.
3. Chrome and browser sessions opened but could not consistently connect.
4. Internet behavior appeared intermittent.
5. User experienced interruptions during active Bible study sessions.
6. Some applications appeared connected while websites failed to resolve properly.
7. IPv6-related connectivity behavior was suspected.

---

## DIAGNOSTIC ACTIONS TAKEN

The following troubleshooting steps were performed:

1. Verified basic network connectivity using terminal commands.

Command used:
ping -c 4 google.com

Result:

* Successful ping responses confirmed partial internet connectivity.
* DNS resolution and packet routing were functioning at least intermittently.

2. Reviewed routing configuration.

Command used:
ip route

Result:

* Default gateway was present.
* Wireless adapter routing appeared normal.

3. Investigated browser-specific failures.
4. Investigated DNS and IPv6 behavior.
5. Attempted IPv6 disable operations.
6. Performed reboot and connection restoration procedures.
7. Verified restored browser access after networking corrections.

---

## ROOT CAUSE ANALYSIS

The issue was determined to be related to unstable or incompatible IPv6 networking behavior on the Ubuntu installation.

Although the system maintained partial internet access, browser-based traffic routing became unreliable for specific websites. This produced “site can’t be reached” and address resolution failures even while ping tests occasionally succeeded.

The networking stack appeared to favor IPv6 routes that were either incomplete, unstable, or unsupported within the current environment.

---

## SOLUTION IMPLEMENTED

The following corrective actions were applied:

1. Network routing and connectivity were verified.
2. Browser sessions were restarted.
3. Ubuntu networking state was refreshed.
4. System reboot procedures were performed.
5. Connectivity tests were repeated until stable operation returned.
6. Internet functionality was validated through successful browser access.

Final Result:

* Bible study websites became accessible again.
* Browser connectivity stabilized.
* Internet access was restored for normal use.

---

## WHAT WAS ACHIEVED

1. Internet browsing functionality was restored.
2. Bible study workflow resumed successfully.
3. Ubuntu system networking was verified operational.
4. Chrome browser functionality was restored.
5. User regained access to multiple Bible translations and study resources.
6. Confidence increased in terminal-based diagnostics and Linux troubleshooting.

---

## LESSONS LEARNED

1. Successful ping responses do not always guarantee full browser functionality.
2. IPv6 routing problems can affect browser traffic even when general connectivity appears operational.
3. Terminal diagnostics are valuable for isolating networking failures.
4. Ubuntu networking issues may require reboot or stack refresh procedures.
5. Maintaining calm, step-by-step diagnostics is more effective than changing many settings at once.
6. Browser interruptions can significantly impact focused study and production workflows.

---

## RECOMMENDATIONS GOING FORWARD

1. Keep a small list of known-good diagnostic commands available:

   * ping
   * ip route
   * nmcli
   * systemctl status NetworkManager

2. Continue documenting recurring failures for pattern recognition.

3. Consider permanent IPv6 configuration review if instability returns.

4. Keep Chrome updated on Ubuntu.

5. Maintain backup Bible study resources locally when possible.

6. Test internet stability before recording or livestream sessions for TheRayCode.
